# Reviewed order-of-play ingestion and coverage

Production reads `data/tennis_fixture_ledger.json`. It contains reviewed source observations, not predictions. The committed empty ledger deliberately produces a FAILED scan and invokes no model runtime. The old `data/manual_challenger_fixtures.json` is preserved for history/migration, but neither it nor automatic discovery bypasses the new gate. Champion artifacts, registration, weights and routing are unchanged.

## 1. Diagnose source access from GitHub Actions

Run **Order-of-play source diagnostic** from Actions. Enter the first Pacific calendar date and number of days, plus current ATP, WTA and Tennis.com schedule URLs. The canonical tennis publishers are `atptour.com`, `wtatennis.com` and `tennis.com`; the shorthand names atp.com and wta.com are not treated as verified tennis publishers.

The ATP default is its current-scores landing page; the diagnostic follows up to three same-publisher `daily-schedule` or `order-of-play` links. Supply a specific tournament daily-schedule URL if that landing page is blocked or only exposes JavaScript. The WTA default is the 2026 Ningbo order-of-play page: update this event-specific URL as the calendar changes. The Tennis.com `{date}` template expands to **every UTC date overlapping the Pacific window**. Arbitrary URL templates may use the same token. Other pages may use their own date selectors; a successful fetch does not establish the requested date's slate.

The workflow uses direct HTTP with bounded requests and no login, browser, scraping service or model runtime. Its Actions summary and downloadable JSON/Markdown artifact report:

- requested and final URL, HTTP status, actual bytes read, declared Content-Length and content type;
- whether recognizable match rows were found, count of row signals and detection method;
- failures, unsupported PDF content, timeouts and pages with no recognized rows.

`match_rows_present: null` means the content could not be assessed; `false` means no supported row structure was found. Neither means a confirmed empty slate. A 200 page can still be a JavaScript shell. Row signals may include completed matches or doubles and do not certify automatic ingestion, timestamps, freshness or coverage. No predictions are generated by this workflow. Pull requests changing the diagnostic also run it so runner-specific results are reviewable before merge.

Local equivalent:

```sh
python scripts/diagnose_order_of_play.py --start-date 2026-10-21 --days 1
```

## 2. Paste a source's order of play

Keep raw pasted pages and context files under ignored `work/`. Parse each source page separately; source receipts from distinct publishers are compared later. The importer accepts these explicit forms (names must match the reviewed identity map):

```text
10:00 | Player Alpha | Player Beta | source-match-123
```

The same four fields may be tab-separated. It also accepts `10:00 Player Alpha vs Player Beta`, or four lines containing `Starts At 10:00`, the first player, `Vs`, and the second player. The latter forms require the source match ID in `match_ids`. 12-hour times such as `8:30 PM` are accepted. Different tournaments, dates, rounds or formats need separate context files/receipts.

Unknown lines cause a line-numbered error and no output replacement. Remove page navigation/headings before importing; do not remove matches just to make parsing pass. `Followed by`, `Not before`, unresolved players, doubles, missing IDs, duplicate fixtures, nonexistent local times and ambiguous daylight-saving times are rejected. Recheck the source for a definite scheduled start; never infer times from court order. This intentionally conservative importer is not a universal page-layout parser.

Example context schema (illustrative values only; replace every fact with verified source facts before use):

```json
{
  "source_url": "https://www.atptour.com/en/scores/current/EXAMPLE/ID/daily-schedule",
  "observed_at": "2026-10-21T16:00:00+00:00",
  "reviewer": "reviewer's name",
  "tour": "ATP",
  "regime": "main",
  "tournament": "Example Open",
  "tournament_key": "example-2026",
  "source_event_id": "actual-provider-event-id",
  "local_date": "2026-10-21",
  "venue_timezone": "America/Los_Angeles",
  "surface": "Hard",
  "round": "R16",
  "best_of": 3,
  "deciding_tiebreak_target": 7,
  "surface_source": "https://www.atptour.com/VERIFIED-EVENT-PAGE",
  "format_source": "https://www.atptour.com/VERIFIED-FORMAT-PAGE",
  "players": {"Player Alpha": "actual-source-player-id-a", "Player Beta": "actual-source-player-id-b"},
  "match_ids": {"Player Alpha vs Player Beta": "actual-source-match-id"},
  "complete_buckets": [
    {"tour": "ATP", "utc_date": "2026-10-21", "whole_tour_date_reviewed": true}
  ]
}
```

Use `ATP/main`, `WTA/main`, `ATP/challenger` or `WTA/wta125` (and `_qualifying` regimes when confirmed). `tournament_key`, full player names, round and format must agree between the two sources; provider IDs may differ and are retained in the verification record. No IDs, players, surfaces or formats are inferred by the importer. Venue timezones must be IANA names, such as `Asia/Shanghai`; UTC is calculated using that venue's actual offset on the scheduled date.

A `complete_buckets` entry is a reviewer assertion that **all tournaments and qualifying in that entire tour/UTC-date bucket** were checked at that publisher. Do not mark a whole tour complete just because one tournament's page was parsed. Leave it empty if completeness has not been checked. For several event receipts from the same publisher, completeness is asserted only after reviewing the combined slate. Explicit verified zeros require a reviewed receipt with `confirmed_empty: true` in the context, an empty paste, and the relevant whole-tour/date scopes. Never infer zeros from missing pages.

```sh
python scripts/import_order_of_play.py paste --input work/atp-paste.txt --context work/atp-context.json --output work/atp-source.json
python scripts/import_order_of_play.py paste --input work/tennis-paste.txt --context work/tennis-context.json --output work/tennis-source.json
python scripts/import_order_of_play.py assemble --sources work/atp-source.json work/tennis-source.json --start-date 2026-10-21 --days 1
```

`--input -` accepts pasted standard input. Add all event receipts from each publisher to `--sources`. The parser stamps the review time, retains the exact source URL and a hash of the pasted text, and validates fields. Parsing outputs **PARSED_UNVERIFIED**; it does not certify a source as truthful. The reviewer must verify that the text and IDs came from the recorded page. Assembly recomputes verification and writes the production ledger only when at least one upcoming fixture is supported by two independent publishers. A FAILED assembly writes the coverage report but leaves any existing ledger unchanged. Runtime always revalidates its timestamps, so an old ledger cannot become fresh merely because it was retained.

## Coverage and inference rules

`TENNIS_SCAN_DATE` selects the first America/Los_Angeles calendar date; default is today's Pacific date. `TENNIS_SCAN_DAYS` defaults to 1 (maximum 7). Set these to the same window used for assembly. The UTC interval is half-open, including its start and excluding its end. A Pacific day may span two UTC dates and be 23 or 25 hours across daylight-saving changes.

Each source must have a reviewer, paste receipt, and observation/review timestamps within the last 12 hours. ATP subdomains and multiple ATP URLs count as **one publisher**, likewise WTA and Tennis.com. Rows are matched by tour, tournament, normalized full player names, UTC start, regime, surface, round and format. Equal counts with different players or start times do not verify fixtures.

Every scan reports all four categories (`ATP`, `WTA`, `ATP_CHALLENGER`, `WTA125`) for every overlapping UTC date. Counts include all rows whose start is inside that interval, even already-started matches; only upcoming verified rows can enter inference. Missing source scopes are `null`, never zero. Count tolerance is exactly zero.

- **COMPLETE:** at least two publishers explicitly cover every tour/date bucket, their counts agree, and the verified ledger accounts for every fixture.
- **PARTIAL (reasons):** at least one upcoming row is independently verified, but a tour/date source is missing, counts disagree, fixture facts conflict, or fixtures change during inference. Only verified rows are scored.
- **FAILED:** empty/unverified ledger, invalid or stale source evidence, no upcoming verified fixtures, failed recheck, or no usable model predictions. No predictions are published.

The source-access diagnostic is not a completeness reference. Counts come from separately reviewed publisher observations, not from the ledger compared to itself. The scan checks the ledger before staging or calling models and again before projecting results. Publication validation rejects available scans without the coverage matrix and two-publisher evidence. Each snapshot and console report includes the status, reasons, Pacific/UTC window and per-source/tour/date counts; the dashboard shows the coverage summary.

A manual source URL and hash establish an audit trail, not cryptographic proof of a webpage. Human review and independent publisher evidence remain required. No live fixtures or successful live predictions are bundled with this implementation.
